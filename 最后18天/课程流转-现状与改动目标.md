### `complete_lesson` 的行为规格

```
入参：{ action: 'complete_lesson', orderId, lessonIndex, userId }
```

| 环节 | 行为 |
|---|---|
| 权限 | 本课程的**教练**（`isAcceptor`）或**发布者**（`isPublisher`）；actor role 分别记为 `coach` / `publisher` |
| 状态门槛 | 必须非终态，且必须 `in_progress`（`editing` / `awaiting` 阶段没有执行教练） |
| 幂等 | 该课节已是 `DONE` → 直接返回 `alreadyDone: true`，**不重复自增** |
| 写课节 | `schedule[i].status = 'DONE'`、补 `completedAt`、`logs` 追加 `lesson_complete` |
| 写进度 | `course_flow_info.progress_done: _.inc(1)` —— 与状态**同一事务**原子提交 |
| 写状态 | 全部课节 DONE → `to: completed`（并写 `completedAt`、追加 `dl` 后缀）；否则 `to` 保持当前值，owner 走同态幂等分支 |
| B 侧同步 | 完成后调 `syncCoachResultToBIfNeeded(nextOrder, 'lesson_completed')`，失败只 warn 不影响本端 |

**为什么 `progress_done` 自增放在这里而不是 owner**：一节课完成 = 一次自增；整单完成只是顺带把状态推到 `completed`，不该再算一次进度。

## 0.7 缺陷修复 · 2026-10-10（执行教练「无权操作每日总结」）

**现象**：执行教练接取课程后，在每日总结 tab 能填、能点保存，但后端返回 `403 无权操作`。

**根因**：`_common.js` 的 `isAcceptor` 只看 `order_base_info.acceptor*`，而**两条接取链路**（`assign_coach_by_pickup_code` / `confirm_coach_binding`）**都只写顶层的 `assignedCoachToken` / `assignedCoachOpenid`，从不修改 `acceptor*`**；偏偏 `acceptor*` 在建单时被写成了发布者自己（`index.js` 的 `publishOrder`、`_sync.js` 的桥接建单）。

⇒ 「接取教练」这个身份在 `isAcceptor` 里**永远判不出来**。而前端 `publish.js:317-319` 的 `isAssignedCoach`（看 `assignedCoach*`）算出的 `canWriteSummary` 是 `true`，**两边口径直接打架**。

**同根问题之前踩过一次**：`index.js:353-357` 有一段注释记录了 `listMyself` 的同一根因，当时只补了列表查询口径，`isAcceptor` 本身没修。这次把根上修掉。

**受影响的三处**（全部返回 403「无权操作」）

| # | 位置 | 功能 |
|---|---|---|
| 1 | `_lesson.js` `updateLessonContent` | **填每日总结**（用户报的这条） |
| 2 | `_lesson.js` `completeLesson` | 标记课节完成 |
| 3 | `_state.js` `closeOrder` | 结课 |

**修法**（`_common.js`）

1. `isAcceptor` **追加执行教练口径**：额外比 `assignedCoachOpenid` / `assignedCoachToken`。
   **只新增放行、不减少任何原有放行** —— 不会让任何原本能操作的调用变失败，零回归风险。
2. 新增 `isAssignedCoach(order, openid, userId)`（只看 `assignedCoach*`，不含发布者 / `acceptor*`），供需要精确区分「教练 vs 发布者」的场景使用。
3. `completeLesson` 的 `actorRole` 判定改用 `isAssignedCoach` —— 原来用 `isAcceptor` 会把发布者自己错记成 `coach` 角色（因为 `acceptor*` = 发布者）。

**为什么是「非机构教练」发现的**：机构场景里建单者常与执行者是同一人（自己建单自己上课），`acceptor*` 恰好等于操作者，掩盖了问题；换成非机构教练接取（操作者 ≠ 建单者）就必然命中。**本质是所有人都会中，只是被掩盖过。**

**实测**：`_common.js` / `_lesson.js` / `_state.js` 全部 `node --check` 通过；IDE lint 0 错误；其它云函数里 `acceptor*` 只作**写入**（`twowaybinding` 建单），没有同类判定问题。
